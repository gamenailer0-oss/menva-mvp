| **Generic, oversaturated tags (#love, #instagood, #foodie-style catch-alls) are a classic bot pattern** — bots and low-quality accounts pile onto huge generic tags because they're easy to find and easy to game, and stacking a post with them is itself read as a spam signal by the algorithm now. Recycling the identical hashtag set on every post is separately flagged as a spammy pattern. | [Sked Social — How to use hashtags in 2026](https://skedsocial.com/blog/how-to-use-hashtags-on-instagram-in-2026-hashtag-tips-to-up-your-insta-game); [Lilach Bullock — why is Instagram limiting hashtag reach](https://www.lilachbullock.com/why-instagram-limiting-hashtag-reach/); [EvergreenFeed — how many hashtags for Instagram in 2026](https://www.evergreenfeed.com/blog/how-many-hashtags-for-instagram/) |

**What this means for MENVA's captions:**

1. **The calendar's existing habit of 3–5 hashtags, always led by `#menva`, is already correct** under the December 2025 cap — no structural change needed, only which 3–5 tags go in the remaining slots (see §5).
2. **The caption itself, not the hashtag block, is now the main discovery lever.** MENVA's captions already put "Lahore," "restaurant," "3D," "menu" in plain English (per `plan.md` §2) — that habit should hold in every caption's first line specifically, since that's the part visible pre-tap and the part search weighs most.
3. **Alt text is a second, underused discovery channel.** The calendar already writes one alt line per post — worth keeping it descriptive and keyword-natural ("A real steak board scanned in 3D, on a table in Lahore"), never a stuffed list of tags disguised as a sentence.
4. **Stop repeating the identical 3rd/4th hashtag across dozens of posts.** The current calendar leans hard on the same `#lahoreeats` / `#foodiesoflahore` / `#lahorefoodie` rotation almost interchangeably as filler (see §5) — the research above flags exact-repeat sets as a spam signal, so picking deliberately per pillar (§3's rotation sets) is worth doing.
5. **Location tagging is a real lever but a real risk for MENVA specifically**, because the pilot restaurant's identity and neighbourhood must never be revealed (BRIEF.md rule 2). A broad city tag ("Lahore, Pakistan") is safe; anything narrower risks functionally outing the pilot restaurant's location even without naming it. Flagged in Needs Abdullah.

These are drawn from the same neighbourhood/geography names already verified as active Lahore food zones in `research/genz-culture.md` (MM Alam Road, Gulberg, Johar Town, DHA), plus the plain-English phrasing `plan.md` already specifies for captions ("Lahore," "restaurant," "menu," "3D"). No third-party keyword-volume tool could be reached in this research pass to attach search-volume numbers to these terms — treat this list as informed by the sourced research above, not as independently measured search volume.

### Where to put keywords

| Field | Rule | Why |
|---|---|---|
| **First line of the caption** | Put the post's main keyword in plain words before the "more" cutoff (roughly the first ~125 characters) — e.g. "Lahore," "3D menu," "restaurant." | It's the only line most scrollers read, and it's a confirmed search-matching signal. |
| **Alt text** | Write one natural, descriptive sentence that would make sense read aloud, including the dish/location/product word where true — never a keyword list. | Alt text feeds search matching but keyword-stuffing is explicitly called out as hurting both accessibility and ranking. |
| **Name/display field** (account-level, not per-post) | Consider adding a keyword to the Instagram account's display Name field (distinct from @handle) — e.g. "MENVA — Lahore 3D menu" — since Instagram search matches the Name field directly. | This is a one-time account setting, not something `calendar.json` controls — flagged as Needs Abdullah below. |
| **Bio** | Same logic as Name — "Lahore," "3D," "AR menu" belong in the bio in plain words, once, not repeated. | Bio text is matched by search the same way captions are. |

### Location-tag strategy

- **Safe:** tag the post's location as the broad city ("Lahore, Pakistan") — matches the research on location tags still feeding ranking, and reveals nothing about the pilot restaurant.
- **Risky, needs Abdullah:** any neighbourhood-specific geotag (Gulberg, a cross-street, a plus-code) on a post that also shows one of the four real dish scans. Because the pilot restaurant is in Gulberg III (`CLAUDE.md`, internal fact) and BRIEF.md rule 2 forbids revealing the pilot restaurant's identity without sign-off, a repeated specific-neighbourhood tag on dish content is a realistic way to accidentally out it, even with no name or logo shown.
- **Technical open question:** whether the n8n → Gotenberg → Instagram publishing pipeline (per `plan.md` §6) currently supports attaching a location tag at all is unknown from this file's scope — flagged as Needs Abdullah, since it's a pipeline/product decision, not a copy decision.

**No location/neighbourhood hashtags currently used** (e.g. `#gulberg`) — correctly absent, and per §2/§4 above this should stay that way for any post tied to the pilot restaurant's actual dishes, without Abdullah's explicit sign-off.
